# Role View (first live slice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clicking a role in Career History shows that role in the middle and its History by year on the right, using data a role already has.

**Architecture:** History-by-year logic lives in `core/role-history.ts` (pure, tested). The middle (`web/src/RoleView.tsx`) and the right panel (`web/src/RoleHistoryPanel.tsx`) are drawn by `HomeCenter` when Home's page is `history` and a role is focused. Career History's list reports the open role up to Home, which keeps it in the address (`#/history/<id>`).

**Tech Stack:** TypeScript, React, Vitest, plain CSS.

**Spec:** `docs/superpowers/specs/2026-11-23-role-view-design.md`

**Branch:** `feat/role-view`, cut from `feat/sidebar`.

## Global Constraints

- pnpm; logic in `core/`; commit messages name no other product.
- Cream banner when no cover: `#fbf6ee` to `#f4ecdf`.
- History filter options in this slice: All, Notes, Milestones, Events, Achievements. Sort: Newest, Oldest.
- Edit uses the same fields as adding a role: kind, title, organization, place, start, end, current, description, achievements (PUT `/api/work-map/roles/:id`).
- New notes and milestones save through PUT `/api/work-map/roles/:id/details` with the full list for that kind.

## Review Focus

1. A role with no start date, or only a year: History still shows it, without a broken year.
2. A role that ended: its last year says it ended; no "So far".
3. Switching roles while the History search has text: the list is for the new role.
4. Back to the list (← in Career History, or the browser's back): Home's overview returns, and choosing the same role again opens it.
5. A role with nothing but a title: the middle shows the cream banner and invitations, nothing broken.

### Task 1: History by year in core

**Files:** Create `core/role-history.ts`, `core/role-history.test.ts`; export from `core/index.ts`.

**Interfaces — Produces:**
- `type RoleHistoryKind = "start" | "end" | "milestone" | "event" | "note" | "achievement"`
- `type RoleHistoryItem = { id: string; kind: RoleHistoryKind; text: string; date: string /* YYYY-MM or YYYY-MM-DD or "" */; month: string /* "Jun" or "" */ }`
- `type RoleHistoryYear = { year: string; label: string; items: RoleHistoryItem[] }`
- `roleHistory(role: WorkMapRole, options?: { filter?: "all" | "note" | "milestone" | "event" | "achievement"; query?: string; order?: "newest" | "oldest"; now?: Date }): RoleHistoryYear[]`

Rules: start and end come from the role's dates; milestones, events, notes from `details`; achievements take the role's start date. Items with no usable year are left out. Years run newest first by default, items within a year newest first; `order: "oldest"` reverses both. Labels: the start year "Started in <Month>", an ended role's last year "Left in <Month>", a current role's current year "So far", any other year "Year N" counted from the start year. The query matches item text, case-insensitive. The filter keeps that kind; start and end only show under All.

- [ ] Tests first: a current role over three years (labels, order, achievements in the start year); an ended role ("Left in …", no "So far"); filter and query; oldest order; a role with no start date gives `[]`; moments with bad dates are skipped.
- [ ] Implement; `pnpm vitest run core/role-history.test.ts` passes.
