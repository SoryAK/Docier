# My Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A My Tools page where the occupant keeps their own tools and equipment with photos, links each to the roles they used it on, and can add drafts from a batch of photos.

**Architecture:** The record, its checks, drafts, filtering and search live in `core/personal-tools.ts`. Storage is three SQLite tables plus photo files in uploads (`tool-<uuid>.<ext>`), behind `/api/tools` routes in `server/personal-tools.ts`. The web page `ToolsPage.tsx` (grid + panel) follows the approved mockup; a role's Setup reads the tools linked to it.

**Tech Stack:** TypeScript, node:sqlite, Hono, Vite + React, vitest (core and server only).

**Spec:** `docs/superpowers/specs/2026-11-25-my-tools-design.md`. Mockup: https://claude.ai/artifact/DdEgnLKQksNGBP7qoJ22jr (approved as a base).

## Global Constraints

- Menu and page name: **My Tools**, under Tools, wrench icon; also in the icon column.
- Categories are the role-equipment ones: `EQUIPMENT_CATEGORIES` / `EQUIPMENT_CATEGORY_LABEL` from `core/role-gear.ts`.
- Whose it is: `mine | shared | borrowed | rented` → "Mine", "Shared", "Borrowed", "Rented".
- Condition: `"" | new | good | fair | poor`. How well you use it: 1–5 or none.
- The fields used to add a tool are the fields used to change it; add, change, remove sit together in one panel.
- Never published. Nothing from tools reaches the public page, snapshots, or the assistant's prompts.
- Photos: `isAvatarType` types and `PROFILE_AVATAR_MAX_BYTES` from `core/profile.ts`; at most 20 per tool.
- Removing a tool removes its photos (files too) and role links; removing a role takes it off every tool.
- Backups include tools, photos (files), and links.
- Management logic in `core/`. Install with pnpm. Commits: `git -c user.name="Sory Kaba" -c user.email="131464999+SoryAK@users.noreply.github.com" commit`, message ends `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No other product named in copy, commits, or docs.

## Review Focus

1. Add from photos with a non-image or oversized file among good ones: the good ones become drafts, the bad ones are listed back by name, and no file or row is left for them. (Task 2 test `skips files that aren't photos`.)
2. Removing a tool deletes its photo files from disk, not just the rows. (Task 2 test `removing a tool removes its photo files`.)
3. Removing the cover photo makes the next photo the cover; removing the last leaves none. (Task 2 test `the next photo becomes the cover`.)
4. Deleting a role leaves its tools, with no "Used at" pointing at a missing role. (Task 2 test `a deleted role comes off its tools`.)
5. A backup restored into an empty app brings back tools, links, and photo files. (Task 2 test `backups carry tools and their photos`.)

### Task 1: The tool record in core

**Files:**
- Create: `core/personal-tools.ts`
- Test: `core/personal-tools.test.ts`

**Interfaces:**
- Produces:
  - `type ToolOwnership = "mine" | "shared" | "borrowed" | "rented"`; `TOOL_OWNERSHIPS`, `TOOL_OWNERSHIP_LABEL`.
  - `type ToolCondition = "" | "new" | "good" | "fair" | "poor"`; `TOOL_CONDITION_LABEL` (`""` → "Not set").
  - `type ToolPhoto = { id: string; url: string; cover: boolean }`

  - `type ToolInput = Omit<PersonalTool, "id" | "draft" | "photos" | "createdAt" | "updatedAt">`
  - `type ToolInputError = "name-required" | "category-invalid" | "ownership-invalid" | "condition-invalid" | "skill-invalid" | "acquired-invalid" | "amount-invalid" | "role-missing"`
  - `readToolInput(raw: unknown, roleIds: ReadonlySet<string>): { ok: true; value: ToolInput } | { ok: false; error: ToolInputError }`
  - `draftToolName(fileName: string): string`
  - `TOOL_PHOTO_LIMIT = 20`
  - `type ToolFilter = { query: string; category: EquipmentCategory | "all"; draftsOnly: boolean }`
  - `filterTools(tools: PersonalTool[], filter: ToolFilter): PersonalTool[]`
  - `toolsForRole(tools: PersonalTool[], roleId: string): PersonalTool[]`
  - `toolSearchText(tool: PersonalTool): string` (name, maker, model, tags)

### Task 2: Storage and the /api/tools routes

**Files:**
- Modify: `server/db.ts` (three tables, after `role_documents`)
- Create: `server/personal-tools.ts`
- Modify: `server/app.ts` (routes, next to the contact photo routes)
- Modify: `server/work-map.ts` (role delete calls `forgetToolRoleLinks`, beside `forgetRoleDocumentLinks`)
- Modify: `server/portability.ts` (tables, safe-name filter, stored names)
- Test: `server/personal-tools.test.ts`

**Interfaces:**
- Consumes: Task 1's `readToolInput`, `draftToolName`, `TOOL_PHOTO_LIMIT`, `PersonalTool`.
- Produces (HTTP, all JSON unless noted):
  - `GET /api/tools` → `{ tools: PersonalTool[] }` (newest first)
  - `POST /api/tools` body `ToolInput` → 201 `{ tool }`
  - `PUT /api/tools/:id` body `ToolInput` → `{ tool }` (sets `draft` false)
  - `DELETE /api/tools/:id` → `{ ok: true }`
  - `POST /api/tools/from-photos` multipart, repeated field `photos` → 201 `{ tools: PersonalTool[], skipped: { name: string; error: string }[] }`
  - `POST /api/tools/:id/photos` multipart `photos` → 201 `{ tool }`; over the limit → 400 `photo-limit`
  - `DELETE /api/tools/:id/photos/:photoId` → `{ tool }`
  - `PUT /api/tools/:id/photos/:photoId/cover` → `{ tool }`
  - `GET /api/tools/:id/photos/:photoId` → image bytes, `cache-control: private, max-age=31536000, immutable`
  - Errors: input errors 400 with the `ToolInputError` code; unknown tool or photo 404 `not-found`; photo type/size 400 `photo-type` / `photo-too-large` / `photo-empty`.
  - Photo URL: `/api/tools/<toolId>/photos/<photoId>`.
  - `forgetToolRoleLinks(db, occupantId, roleId): void`

Tables:

```sql
personal_tools (id TEXT PRIMARY KEY, occupant_id TEXT NOT NULL REFERENCES occupants(id), name TEXT NOT NULL,
  category TEXT NOT NULL, ownership TEXT NOT NULL, maker TEXT NOT NULL DEFAULT '', model TEXT NOT NULL DEFAULT '',
  serial TEXT NOT NULL DEFAULT '', condition TEXT NOT NULL DEFAULT '', skill INTEGER, acquired TEXT NOT NULL DEFAULT '',
  paid REAL, worth REAL, kept_at TEXT NOT NULL DEFAULT '', tags TEXT NOT NULL DEFAULT '[]', notes TEXT NOT NULL DEFAULT '',
  draft INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, updated_at TEXT NOT NULL)
personal_tool_photos (id TEXT PRIMARY KEY, occupant_id TEXT NOT NULL REFERENCES occupants(id), tool_id TEXT NOT NULL,
  stored_name TEXT NOT NULL, media_type TEXT NOT NULL, is_cover INTEGER NOT NULL DEFAULT 0,
  sort_order INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL)
personal_tool_roles (id TEXT PRIMARY KEY, occupant_id TEXT NOT NULL REFERENCES occupants(id), tool_id TEXT NOT NULL,
  role_id TEXT NOT NULL, created_at TEXT NOT NULL, UNIQUE (occupant_id, tool_id, role_id))
```

- [ ] **Step 1: Write the failing tests** in `server/personal-tools.test.ts`, set up like `server/role-documents.test.ts` (in-memory db, temp uploads dir, `createApp(db, { uploadsDir })`, a tiny PNG as bytes):
  - `adds, reads, changes, and removes a tool`: POST → 201 with `draft: false`, `roleIds: [roleId]`; GET lists it; PUT with a new name and no roles → name changed, `roleIds: []`; DELETE → GET is empty.
  - `refuses a bad tool`: POST `{ name: "" }` → 400 `name-required`; PUT on an unknown id → 404.
  - `adds drafts from photos`: two PNGs `IMG_1.png`, `IMG_2.png` → 201, two tools named `IMG_1`, `IMG_2`, `draft: true`, each one photo with `cover: true`; GET of the photo URL → 200 `image/png`.
  - `skips files that aren't photos`: a PNG plus `notes.txt` (text/plain) → one tool, `skipped: [{ name: "notes.txt", error: "photo-type" }]`, and the uploads dir holds exactly one file.
  - `saving a draft clears it`: PUT on a draft → `draft: false`.
  - `the next photo becomes the cover`: add three photos; cover is the first; set the third as cover → only it is cover; delete it → the first remaining (by `sort_order`) is cover; delete all → `photos: []`.
  - `refuses a 21st photo`: 20 photos then one more → 400 `photo-limit`.
  - `removing a tool removes its photo files`: tool with two photos; DELETE; the uploads dir is empty.
  - `a deleted role comes off its tools`: link a tool to a role; delete the role via the existing role delete route; GET → tool still there, `roleIds: []`.
  - `backups carry tools and their photos`: export (existing backup route), restore into a fresh app/db/uploads dir (as `server/portability-restore.test.ts` does), GET `/api/tools` → same tool, role link, and the photo URL returns the image.
